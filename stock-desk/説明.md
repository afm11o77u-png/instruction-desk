# 在庫管理（試用）

このパソコンの指示書デスク（http://127.0.0.1:8765/）の左上で、「指示書デスク」「顧客・商品情報」「在庫管理」を切り替えます。在庫の中の顧客・仕入先・商品・保管場所・初期在庫・在庫一覧は、見出しの下のボタンで切り替えます。

在庫のデータは指示書とは別のファイルです。場所は `instruction-desk\data\stock.sqlite3` です。指示書の `instructions.sqlite3` には混ぜていません。

会社の指示書デスクの最新版は、このパソコンにあるソースではありません。会社のパソコンへ入れるときは、下の「会社の最新版へ入れるとき」を使います。

架空のサンプルだけを単体で見るときは、これまでどおり `stock-desk` の起動ファイルを使います。

## 起動

指示書と一緒に使うときは、指示書デスクを起動してログインし、左の「在庫管理」を押します。最初は空の台帳です。サンプルの架空データは入りません。

単体で試すとき:

1. `サンプルを起動.cmd` をダブルクリックする。架空の顧客・商品・在庫が入った画面が開きます。アドレスは http://127.0.0.1:8776/
2. 空の台帳を単体で試すときは `起動.cmd`。アドレスは http://127.0.0.1:8775/。この台帳は、指示書デスクの中の在庫とは別ファイルです。
3. 終わるときは、黒い窓で Ctrl+C を押す。

Python 3 が必要です。起動ファイルは、`py -3`、`python`、このパソコンに入っている実行環境の順に探します。別のパソコンでは Python 3 を入れてから同じファイルを使います。追加のライブラリは不要です。

## 操作

- 顧客、仕入先、商品、保管場所は、一覧から検索・追加・修正します。参照した記録は削除せず、使用停止にします。
- 商品では、サイズをまとめて選びます。登録時に「アルファベット」（S、M、L…）、「号数」（5号、7号…）、「ウエスト」（70、73…・単位 cm）を切り替えられます。切り替えても、すでに選んだサイズはそのまま残ります。LL と 2L、「70」と「W70」は別のサイズのままです。特殊サイズは、その場の入力欄から追加します。
- 同じ品番でも商品IDが違えば別商品です。通常の仕入先は仕入先台帳から選びます。仕入先はメーカーではありません。商品一覧では仕入先を選んで、その仕入先の商品だけを閲覧できます。
- 顧客ごとの刺繍・加工は商品の取扱として一度登録します。刺繍ありとなしは別在庫です。その顧客がその仕様だけなら「標準仕様」になり、入出荷のたびに選び直さない形で残せます。入出荷の画面自体は、今回はまだありません。
- 保管場所の一覧は拠点ごとに1行です。棚・区画はその行にまとめ、多いときは「ほか○件」と省略します。「拠点を新しく登録」では空の拠点名から新しい拠点を作り、必要なら「棚を追加」で複数棚を一度に登録できます（棚なしでも可）。既存拠点の棚の追加・修正は一覧の「開く」から行います。空の棚名は保存しません。在庫が紐付いている棚は削除できません。同じ拠点名での新規登録は拒否し、既存拠点を上書きしません。
- 起動時に仮拠点「未確認」（棚なし）を自動で用意します。同名が既にあれば増やしません。旧システムの拠点空欄在庫をいったんここに置き、後から実拠点・棚へ移す運用向けです。拠点は必須のままです。空欄を自動で「未確認」にはしません。
- 初期在庫の保管場所は、先に拠点を選び、棚がある拠点では棚・区画も選びます。棚が無い拠点は拠点そのものが場所です。以前から拠点直下に付いている在庫は「棚指定なし」として残します。
- 初期在庫は、顧客・商品・加工・場所を選んだあと、サイズごとの数量と仕入単価を表で入力します。単価が違う行は分けます。保存前に合計を確認します。仕入単価の空欄は 0円にしません。
- 在庫一覧の数量と金額は、入荷分から計算します。手入力欄はありません。表示は「仕入原価ベースの在庫金額」で、会社全体の資産額や会計上の評価額と同じものではありません。
- 初期在庫の訂正は、入荷分の「訂正」から行います。変更前と変更後の数量・単価・金額が履歴に残ります。

入荷日が分からない初期在庫は、架空の日付を入れず「入荷日不明」にします。運用開始後の入荷より先に払い出す想定です。初期在庫同士の順番が不明なときは、払出し順の小さい番号から出します。単価の安さでは順番を決めません。これは暫定仕様です。

## データの場所

| 種類 | ファイル |
| --- | --- |
| 指示書デスクの中の在庫 | `instruction-desk\data\stock.sqlite3` |
| 単体の空の台帳 | `stock-desk\data\live\stock.sqlite3` |
| サンプル | `stock-desk\data\sample\stock.sqlite3`（初回の `サンプルを起動.cmd` で `sample_data.py` が生成。Git には含めない） |
| バックアップ | 手動コピー、または指示書デスク「管理・修正」の「移行用バックアップを書き出し」（在庫を含む） |

手動で守るときは、アプリを止めてから `stock.sqlite3` と、同じ場所の `-wal` `-shm` があればそれもコピーします。戻すときもアプリを止めてから、そのファイルを同じ場所へ戻します。

動いているデータベースを共有フォルダに置いて、複数台から同時に開かないでください。

サンプル用のファイルを、空の台帳へ自動ではコピーしません。参考のCSVも、本番の初期在庫としては取り込みません。

## 実装済み

- 顧客台帳（内部ID、名前、任意のフリガナ・住所・電話・担当者、使用中／停止）
- 仕入先台帳（内部ID、名前、任意の住所・電話・担当者、使用中／停止）
- 商品台帳（品番は全社共通の一意キーにしない、色、通常の仕入先、複数サイズ、顧客ごとの加工と標準仕様）
- 保管場所（拠点と、その下の棚・区画）
- 初期在庫（サイズごとの表、単価違いの分割、基準日、入荷日または入荷日不明、確認、二重登録防止、訂正と履歴）
- 在庫一覧（顧客・商品・サイズ・加工・場所で絞り込み、商品別・顧客別・場所別・入荷分、単価別の内訳）
- 在庫ロットの状態（新品／中古）。商品・取扱は共有し、ロット側で区分する
- 初期在庫・入庫・出庫・在庫一覧・期間集計・Excel取込で状態を区別（FIFOも状態ごと）
- サンプルデータと空の台帳の分離

## テスト結果

自動テスト 25件、失敗 0件。確認した内容は次のとおりです。

- 同じ品番 SCR-100 を、仕入先が違う商品IDで分けて持てる
- LL と 2L を別サイズのまま保存できる
- 1,000円×10着と1,200円×5着が、15着・16,000円になる。単価の内訳も出る
- 別の顧客、刺繍あり、別の保管場所の在庫は混ざらない
- 入荷日不明は日付を作らず保持する
- M と L を1回の登録で保存できる
- 同じ送信のやり直しは二重に加算しない
- 空欄の単価は0円にせず拒否する
- 10着・10,000円を8着・8,000円に訂正すると、残りの1,200円×5着と合わせて13着・14,000円になり、数量と金額がずれない
- 顧客名を変えても顧客IDと在庫のつながりが残る
- 保存したあと開き直しても、サーバーを止めて起動し直してもデータが残る
- 入荷日不明を、日付のある入荷より先に並べる。高い単価を先にはしない

画面でも、サンプルの在庫一覧で15着・16,000円と単価内訳を確認しました。顧客を「かしわ食品 本店」に絞ると、あおば記念病院の在庫は出ません。空の台帳で、顧客・仕入先・商品（M、L、LL、2L）・石狩倉庫①・初期在庫を登録し、空欄単価の拒否、確認画面、再読み込み、サーバー再起動後の残存、名称変更、8着への訂正を確認しました。画面確認に使った台帳は消し、`起動.cmd` の台帳は空に戻してあります。サンプルはそのままです。

## データ構造と暫定仕様

在庫の本体は「ロット」です。顧客と商品と加工仕様の組み合わせ、サイズ、保管場所、仕入単価、入荷数量、残数量、在庫基準日、入荷日または入荷日不明、払出し順、状態（`condition`：`new`＝新品／`used`＝中古）を1件で持ちます。一覧の数量は残数量の合計、金額は各ロットの残数量×そのロットの仕入単価の合計です（中古を新品単価では評価しません）。

名前を変えても、顧客・商品・場所は内部の番号でつながります。品番だけでは商品を特定しません。旧システムの商品名「＊」は中古の目印でしたが、本機能では商品名を書き換えず、ロットの `condition` で区分します。既存ロットの状態値は保持し、未設定・想定外の値を新品へ一括変換しません（表示は「未設定」）。スキーマ上もともと `DEFAULT 'new'` で入っている行はそのままです。

入荷・出荷・訂正は、`moves` に追記します。初期在庫は `opening`、訂正は `opening_correction` です。出荷は、同じ顧客・取扱・サイズ・場所・状態の中で、入荷日不明を先にし、その中では払出し順、日付があるものは入荷日の順です。単価では並べません。状態をまたぐ自動振替はしません。償却待ちは新規顧客向け作業場などの保管場所名として登録できます。

借用は `loans`、`loan_lines`、`loan_events` に、在庫が減る顧客と使用した顧客、返却、返却不要とその理由を残せる形です。未返却の管理をあとでやめても、この履歴は残します。

## 会社の最新版へ入れるとき

1. 会社側の最新の指示書デスクを基準にする。このパソコンの `instruction-desk` を最新版とは扱わない。
2. 会社側のデータベースとプログラムを、コピーした環境でバックアップする。本番のファイルを直接いじらない。
3. 差分を見てから、この試用アプリの表と画面を足す。試用の `stock.sqlite3` を、会社のデータベースへ自動では混ぜない。
4. このパソコンでは、左の切替と `/inventory/` で在庫を開いています。在庫の計算は `stock.py`、画面は `static` です。会社の最新版へ足すときは、同じ切替をその最新版へ写します。試用の sqlite はコピーしません。
5. このパソコンの切替では、在庫の操作に指示書デスクのログインが必要です。単体の試用版はログインなしのままです。公開前に、単体の「ログインなし・このパソコンだけ」のままインターネットへ出さない。
