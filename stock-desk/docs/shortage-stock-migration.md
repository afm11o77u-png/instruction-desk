# マイナス在庫・原価未確定対応のDB移行／バックアップ

本番の `stock.sqlite3` は直接いじらず、コピーしたテスト用DBで確認してから適用してください。

## 変更内容（スキーマ）

起動時（`server.prepare` → `stock.initialize` → `migrate_schema`）に自動適用されます。

| 対象 | 追加 |
| --- | --- |
| `lots` | `cost_pending INTEGER NOT NULL DEFAULT 0`（1＝原価未確定。不足出庫・棚卸増分など） |
| `moves` | `corrects_move_id INTEGER`（訂正時に元記録IDを残す） |

既存の数量・単価・履歴はそのまま残ります。顧客・担当者・了承データは変更しません。

## バックアップ（自動）

既存DBがあり、上記カラムが未適用のとき、`prepare` がマイグレーション前に隣へコピーします。

- ファイル名例: `stock.pre-shortage-YYYYMMDD-HHMMSS.sqlite3`
- 同じ場所の `-wal` / `-shm` があればそれもコピー

## 手動バックアップ（推奨）

1. アプリを止める（`停止.cmd` またはサーバー停止）
2. 次をコピーする（WAL運用時は3点セット）
   - `instruction-desk\data\stock.sqlite3`
   - `stock.sqlite3-wal`（あれば）
   - `stock.sqlite3-shm`（あれば）
3. テスト用フォルダへコピーしたDBだけで起動・検証する（本番ファイルは触らない）

## 戻し方

1. アプリを止める
2. バックアップファイルを元の `stock.sqlite3` 名に戻す（WAL/SHMも揃える）
3. 起動し直す

## ローカル確認（テスト用DB）

```text
E:\instruction-desk で最新を取り込み → 再起動.cmd
```

1. 本番DBをコピーしたテスト用パスで起動する（サンプル起動でも可）
2. 在庫一覧で「入庫」「出庫」「棚卸」、マイナス絞り込みを確認
3. 「一覧にない商品を入庫」と不足確認後の出庫ができること
4. 在庫履歴から訂正・不足出庫の表示を確認
5. 旧「入庫・出庫」URL（`?section=move`）が在庫一覧へ案内されること
5. 期間入出荷集計・確認用Excelで数量が一致し、原価未確定が確定金額に混ざらないこと
