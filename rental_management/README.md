# ユニフォーム管理の土台

旧システムの画面・データ・帳票を参照せず、新しい台帳として設計。

## 構成

- 入口は指示書デスクの「ユニフォーム管理」。URL は `/rental`。
- ログインは既存の社内セッション。主管理者・管理者・担当者が登録可能、倉庫担当は閲覧のみ。
- 顧客・商品・加工・サイズは現行在庫DBを読み取り専用で参照。顧客の拠点は現行の組織設定を参照。
- 固有データは `data/rental.sqlite3`。指示書DB・在庫DBには台帳や数量を追加しない。
- レンタルDBはGit管理対象外。運用データのバックアップにはこのDBも含める。

## 登録と履歴

1. 契約に顧客・期間・形態・対象制服と枚数を登録。
2. 着用者に顧客内の管理番号・所属・契約・サイズ情報を登録。
3. 個体に顧客・商品加工・サイズ・固有バーコードを登録。管理番号は自動採番。
4. 個体を着用者と契約へ貸与。返却時は貸与行に返却日を記録。

- 契約の枚数は貸与目安の台帳情報。超過の承認・制限運用は今後決める範囲。
- 個体の商品・サイズ・バーコードと、台帳の顧客IDは登録後固定。
- 別顧客を跨ぐ貸与、契約期間外・対象商品外の貸与、修理・廃棄中や既に貸与中の個体の貸与を拒否。
- 社員番号は顧客内、バーコードと個体管理番号は全体で一意。
- 貸与時の着用者・契約・個体情報をスナップショットとして保持。後の改名・契約改定でも当時の情報を確認可能。
- 退職者の未返却を全体画面に表示。物理削除の画面は設けず履歴を保持。
- 在庫数量の引当・出庫・入庫は実行しない。倉庫の在庫行QRと個体バーコードは別。
- WEB依頼の既存契約は初期内容の参照元として選択可能。参照キーを一意に保持し、レンタル側で同じ参照先を重複作成しない。以降の変更は双方へ自動同期しない。

## データ量と拡張

台帳・履歴は顧客と関連IDの索引で検索し、APIは50件ずつ取得する。個体の有効貸与には部分一意索引、更新には版数、書き込みにはトランザクションを使う。

`external_key` は将来の取り込み時の対応キー用。現時点で旧データの取り込みは行わない。洗濯工程・請求・料金計算・返却紛失の精算・取込書式は未実装。

現行の管理・修正の分割バックアップには専用DBをまだ連動していない。実運用データを入れる段階で、マスタとの整合性を保つバックアップ／復元を追加する。

## レンタル・クリーニングの共通管理（スキーマ2）

- 契約 `service_type` はレンタル／クリーニングのみ。`default_ownership` は新規個体登録時の入力補助。所有区分を人の属性にはしない。
- 制服個体 `ownership` は自社所有／顧客所有／着用者所有／その他／未確認。契約の初期値を入力しても個体で変更でき、着用者の変更や解除では変わらない。後から契約の初期値を変更しても既存個体には波及しない。
- `wearer_contracts` で着用者と複数の利用契約を関連づける。レンタルとクリーニングの混在可。旧 `contract_id` は互換用の先頭契約として保持。
- 共通の利用履歴 `loans.relation_type` は貸与／着用登録。クリーニング契約は着用登録・着用解除、レンタル契約は貸与・返却に限定する。同一個体の同時利用はどちらの区分も一件まで。
- 適用する契約は着用者の利用契約に含まれ、顧客・商品・有効期間が一致する必要がある。着用登録は個体の所有区分が未確認なら拒否。
- 集計は貸与中と着用登録中を別に表示。退職者の返却待ちはレンタル貸与に限定する。洗濯の入荷・工程・納品履歴は今回の着用登録と別で、今後追加する。
- 旧スキーマの既存契約はレンタル、既存利用履歴は貸与、既存個体の所有区分は未確認で移行。旧着用者の単一契約は関連テーブルに一度だけ転記。再起動を繰り返しても解除済みの契約は復活させない。

## 顧客・契約の共通設定

指示書デスクの `/customer-contracts` を唯一の契約登録画面とする。既存WEB依頼の共通・地区・拠点設定と権限、版数による競合検出、下書き・公開の分離を利用する。WEB依頼の旧設定ボタンは共通設定に移動し、ユニフォーム側は顧客・契約を引き継ぐリンクを表示する。戻り先は同一オリジンの既知ページのみ許可。

契約・制服・枚数の正本は指示書DBの設定下書き。ユニフォームDBの `contracts` / `contract_lines` は貸与・着用者の既存整数IDを維持する参照用投影で、独立した保存を拒否する。読み取り・利用操作の前に最新下書きから同期し、変更時だけ版数を増やす。削除された契約の投影は停止し、履歴や着用者リンクを削除しない。過去の貸与スナップショットはそのまま。

起動時、独立登録済みの契約は共通下書きの引継ぎ部署へ一度だけ移す。既存WEB参照に紐づく契約は同じ契約へ統合し、WEB側にない期間・取引区分等の補足情報のみ補完。公開済みスナップショットは変更しない。移行前には指示書DBとユニフォームDBを整合したバックアップとして保管する。
