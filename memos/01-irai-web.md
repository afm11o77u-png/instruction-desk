# 依頼WEB（顧客からの受注ページ）構成案
## 顧客側（外から見るページ）
1. ログイン：顧客ごと、できれば部署ごとのIDでログイン。利用者管理に「顧客」権限を足し、自分の顧客・部署の分だけ見られる。
2. 制服を選ぶ：在庫管理の商品と在庫から、その部署で使える制服だけを写真付きで表示。サイズと数を選んでカートへ。在庫の有無も表示。
3. 依頼を送る：着用者名、納品希望日、備考を入れて送信。依頼番号を表示し、確認メールも送れるように。
4. 依頼履歴：受付中、準備中、出荷済みなどの状況を確認できる。
## 社内側（指示書デスクの中）
5. 受注一覧：届いた依頼を新しい順に表示、未処理にバッジ。開いて内容確認し「受付」か「差し戻し」。
6. 在庫とつなぐ：受付すると在庫管理の出荷予定に。足りない分は今の「発注」ボタンと同じく発注フォームへ引き継ぎ。
7. 指示書とつなぐ：加工（刺繍・ネームなど）があれば、そのまま指示書を作成。
## 土台
- 顧客の下に部署を作り、部署ごとに使える商品（採用品）を登録。
## 進め方
- 最初は 1・2・3・5 と部署の土台だけで小さく始め、在庫や指示書とのつながりは後から足す。
## 関連：クリーニング・レンタル
- 従業員の登録から始める（誰が、どの制服を、何枚持っているか）。従業員を顧客・部署にぶら下げ、依頼WEBの部署と共通にする。
- 順番：「顧客・部署・従業員」の土台 → 依頼WEB／クリーニングを乗せる。
